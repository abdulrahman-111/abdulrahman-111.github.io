## The problem

Organizing workshops, webinars, and conferences requires more than storing an event title. Participants need to find events and register, while organizers need to change schedules and manage capacity without losing registration information.

## My contribution

I worked on this team-built C++ application with user login, scheduling, dynamic waitlists, and SQLite persistence. The project applies object-oriented design and the Factory and Singleton patterns to event management.

## Design and implementation

The application models multiple event types and uses the Factory pattern to support their creation. The Singleton pattern provides a central event-management instance. SQLite stores user accounts, events, registrations, waiting lists, and feedback.

The repository separates event management, event types, user management, and database access into C++ classes. This gives the project concrete boundaries between domain behavior and persistent storage.

## Workflows

Organizers can create and update events, postpone or cancel them, and manage participation. Participants can browse and search events, register, join a waitlist when capacity is reached, and leave feedback.

This is an event-management project; the documented scope is scheduling and participation rather than hosting video calls.
