## Context

Career-mode decisions combine several kinds of evidence. A squad-planning question is not the same as predicting an injury, valuing a player, estimating an event outcome, or simulating a match. This collaborative project brings those tasks into one analysis system while preserving their different targets and limitations.

The work covers match simulation, player development and squad planning, transfer decisions, dashboards, and an automatically generated `.docx` scouting report. Its value is not a single headline score; it is the way separate models feed a decision-support workflow.

## System capability

The overall team system includes match simulation, player development and squad planning, and a transfer-decision workflow. It can produce a generated `.docx` scouting report so model outputs and supporting analysis can be reviewed as an artifact rather than only as console output.

Project-reported position-classification accuracy is 82.82%. Project-reported overall-rating R² is 0.9801. Project-reported injury accuracy is 95.0%. Project-reported injury recall is 96.25%. Project-reported shot-outcome accuracy is 89.7%. Project-reported match-winner overall accuracy is 51.7%.

Those results belong to the collaborative project. My verified scope is the transfer-decision engine described below, not every model in the repository.

## Architecture

The system is organized around related but distinct decision domains:

1. **Player understanding** supports position and rating analysis.
2. **Squad planning** uses player-development and roster information.
3. **Match analysis** covers shot outcomes and winner prediction.
4. **Transfer decisions** combine injury risk, performance prediction, and market-value information.
5. **Decision presentation** turns analysis into dashboards and a generated scouting document.

This separation prevents one strong model from masking a weaker one. A high rating fit does not validate a match-winner model, and a transfer recommendation should preserve the provenance of each contributing signal.

## Constraints and trade-offs

The repository's limitations are part of the result. The overall-rating performance reflects structured FIFA ratings; it should not be generalized into a claim about open-ended player quality. Project-reported match-winner overall accuracy is 51.7%, which is weak, so that model is not a reliable decision boundary simply because it is part of the same system.

The datasets also need standardization. Differences in feature names, units, missing values, or categorical encodings can make a pipeline appear to work while joining incompatible meanings. Standardization work is therefore a prerequisite for comparing or composing model outputs responsibly.

Generated reports introduce another trade-off. A `.docx` artifact improves reviewability, but polished presentation can make uncertain predictions look more authoritative than they are. Reports and dashboards need to retain metric labels and limitations instead of flattening every signal into a definitive recommendation.

## Implementation

The implementation connects analytical components through a decision workflow rather than treating them as one model. Match simulation and player-development/squad-planning capabilities address their own questions. The transfer path brings together an injury classifier, performance prediction, and market-value work before producing dashboard views and an automated scouting report.

The generated `.docx` report is an output boundary: it packages analysis for review. That boundary is useful because it forces the system to decide which inputs, predictions, and caveats belong in a scouting artifact, while dashboards provide a more interactive view of the same decision space.

## Outcomes and learning

The results demonstrate why model-specific evaluation matters. Project-reported position-classification accuracy is 82.82%. Project-reported overall-rating R² is 0.9801 on structured FIFA ratings. Project-reported injury accuracy is 95.0%. Project-reported injury recall is 96.25%. Project-reported shot-outcome accuracy is 89.7%. Project-reported match-winner overall accuracy is 51.7%.

The learning is as much about restraint as prediction. A decision-support system should expose weak components, dataset standardization needs, and the scope of each metric. Combining models becomes useful only when the interface preserves those boundaries rather than manufacturing confidence from aggregation.
